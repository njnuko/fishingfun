# FishingFun v48 — 判据去色相化

> 版本：v48（2026-11-01）
> 触发问题：用户指出「魔兽里面会随着光线的不同，浮标的色调也会看上去不一样」
> 结论：**「暖色」从来不是浮标的属性，只是某几种光线下的巧合。v46~v47 的暖色闸门是一条会随光照随机失效的判据。**

---

## 一、一句话结论

v46 起所有锚点都要过一道「邻域暖色像素 ≥ 20」的闸门。这条判据在真机上会把**真浮标**判成「该处没有浮标」——因为浮标颜色随魔兽环境光变化。v48 把判据换成与色相无关的**局部高对比亮团**：亮度显著高于周围水面 + 边缘清晰成团。暖色降级为日志里的参考信息，不再当门槛。

---

## 二、证据：这张图上暖色判据到底有多不靠谱

### 2.1 逐像素实测（真机区域帧，1280×801）

被测帧：用户 2026-11-01 上传（`img_2d27b1fa00a9`），浮标本体 bbox `x488..519 y321..344`（31×23 px），质心 `(504,331)`。

| 度量 | 真浮标邻域 | 空白水面 A | 空白水面 B | 水面最强反光 |
|---|---|---|---|---|
| 暖色像素（R−B>20 且 R>80） | **149** | **129** | 13 | 0 |
| `dev>30` 亮团像素（v48 判据） | **720** | 22 | 39 | 56 |
| `dev` 峰值 | **126** | 42 | 46 | 50 |

两列数字说明两件事：

1. **暖色完全分不开**：真浮标 149 px，一片空白水面的波纹反光 129 px。判据门槛是 20，两边都远超——暖色判据在「水面有反光」和「有浮标」之间几乎无法区分。
2. **亮团分得开**：720 vs 56，13 倍。而且峰值 126 vs 50，是 2.5 倍。

### 2.2 光照鲁棒性：新判据全过，旧判据直接崩

对同一帧做 7 种色相/亮度变换，两条判据各跑一遍（锚点取真浮标 `(501,332)`）：

| 光照变换 | 旧暖色判据 | 旧结论 | v48 亮团判据 |
|---|---|---|---|
| 原始（暖橙） | 750 px | 通过 | 通过 |
| 冷光·全蓝化 `×[0.55,0.75,1.15]` | **0 px** | ❌ **误拒真浮标** | 通过 |
| 去饱和·白灰 | **0 px** | ❌ **误拒真浮标** | 通过 |
| R/B 互换（纯冷色浮标） | 149 px | 通过 | 通过 |
| 整体压暗 50% | 490 px | 通过 | 通过 |
| 整体提亮 30% | — | — | 通过 |
| 黄变青 | — | — | 通过 |

**「全蓝化」和「去饱和」这两行就是用户描述的那个场景**：晨昏偏冷、阴影里、晴天正午过曝，浮标看上去是白的/青的，`R−B` 不再是 +150 而是 0。这时候暖色闸门 100% 拒绝真浮标，上层收到「该处没有浮标」，于是标定失败 → 重抛 → 反复。

而亮团判据的物理意义是「水面上凸出来的、被光照到的小物体」，跟它是橙色、白色还是青灰色无关。

## 三、v48 具体改了什么

### 改动 1：锚点闸门 `_anchor_has_bobber()` 换判据

`fishingfun/fishbot.py`

| 项目 | v47 | v48 |
|---|---|---|
| 邻域半径 | 20（40×40 窗口） | **30**（60×60 窗口） |
| 通过条件 | 暖色像素 ≥ 20 | 亮团像素 ≥ 90 **且** 峰值 ≥ 70 **且** 占比 ≥ 3% **且** 亮团质心离锚点 ≤ 0.8×半径 |
| 暖色的角色 | **唯一门槛** | 日志参考值，不参与判定 |

邻域半径放大是有实测依据的：浮标本体 31×23，加 ±5px 抖动就已经占满 40×40 窗口，锚点只要偏 8px 浮标就有半个身子出框。

质心约束是新加的兜底：防止「锚点在一片空水面上，但窗口边缘恰好扫到一个浮标或其他亮点」被误判为通过。

### 改动 2：检测主路径判据改为「暖色 ∪ 亮团」并集

`fishingfun/searchbobberfinder.py` · `_find_bobber_by_diff()`

v47 及以前：

```python
if not mask.any() and getattr(self, "bobber_bright_enabled", False):
    mask = self._bright_blob_mask(bmp)   # ← 只有暖色一个都没有时才走这条路
```

问题有两个：默认值是 `False`（等于这条路根本没开）；而且是「找不到才试一下」的备选，不是并列判据。

v48：

```python
warm_mask   = mask                    # 暖色像素
bright_mask = self._bright_blob_mask(bmp)   # dev>30 的亮团像素

if bright_mask.any():
    mask = (warm_mask | bright_mask) if warm_mask.any() else bright_mask
```

两条判据来自同一个物理事实（浮标是水面上受光的凸出物），取并集不会互相污染；任一命中就进后续的团块筛选与三帧确认。

`__init__` 里默认值同步改为 `bobber_bright_enabled = True`。

### 改动 3：日志措辞

旧：`锚点校验: 局部 (x,y) 邻域暖色 149 px（门槛 20）→ 通过`
新：`锚点校验: 局部 (x,y) 高对比亮团 772 px(占比21%) 峰值152 质心偏移3px（暖色750 px 仅参考）→ 通过`

一看日志就能知道是哪条判据在起作用、亮团分离度多少、以及「暖色」现在是参考值。

跑起来后重点看这三行日志：


判读标准：

- **亮团 px ≥ 90 且"通过"**：闸门工作正常。
- **浮标明明在、但"拒绝（该处不是浮标亮团）"**：说明阈值仍偏严，看日志里的 px 和峰值，记下来发我，按实际数字调 `MIN_BRIGHT_PX_AT_ANCHOR`。
- **满屏都是"通过"但锚点乱跳**：说明亮团判据在水面反光强的钓点过于宽松，需要恢复「质心偏移」或加「团块长宽比」约束。
