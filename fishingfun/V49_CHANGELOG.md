# FishingFun v49 变更说明

生成时间：2026-11-02
上一版：v48

---

## 一、这一版修的是什么

v48 的真机日志（720×529 环境）停在这一段：

```
08:56:32,922 色差浮标命中: (268,216) 23x37 area=313 (连续 4 帧)
08:56:33,039 色差检未命中（1/3）
08:56:33,090 色差检未命中（2/3）
08:56:33,139 色差检未命中（3/3）
08:56:33,140 ⚠️ 连续 3 帧找不到浮标 —— 本竿已锁定过浮标，判为目标消失/咬钩
08:56:33,141 Bot has Stopped.
```

这里同时暴露了两个问题：

1. **该提竿的时候没提竿。** 浮标面积 457（锚定）→ 313（最后一条命中）→ 消失，
   这是鱼把浮标往水里拉的典型曲线，本应立刻右键提竿收鱼。
2. **该重抛的时候没重抛。** 就算按「目标消失」处理，日志上一行还在说
   「重抛继续」，下一行就是 `Bot has Stopped.` —— 前后矛盾。

## 二、五处改动

### ① 停机根因：`run.py` 的 `_on_no_bobber`

原代码在「本竿锁定过浮标」分支里打印完「重抛继续」后，**无条件**执行：

```python
bot.is_enabled = False
```

而主循环是 `while self.is_enabled:`，这一句下去循环立刻结束，所以必然打印
`Bot has Stopped.`。「重抛继续」从来没生效过。

现改为区分**软停 / 硬停**：

| 情形 | 动作 |
|---|---|
| 本竿锁定过浮标，之后丢失 | 软停：`_soft_stop=True` + `is_enabled=False`，循环末尾清标志、`is_enabled=True`，0.35 秒后重抛 |
| 本竿从未锁定浮标 | 硬停：提示检查浮标可见性，真正退出 |
| 标定期间丢失 | 不判停机，只记日志 |

### ② `reset()` 的计数残留（重抛后秒停的隐藏原因）

`SearchBobberFinder.reset()` 原来清 `previous_location`、`_area_hist`、
`_diff_*`，但**没清 `no_bobber_frames`**。

后果：上一竿凑满 3 帧触发停机后，计数器停在 3。新一竿抛下去，第一帧只要
miss 一次就再次 `>= no_bobber_limit(3)` → 立刻又触发一次 abort。
也就是说光修 ①，重抛之后还是会秒停。

现在 `reset()` 一并清零。

### ③ 标定期不判停机

首竿要连续采样 17 秒反推咬钩幅度。这 17 秒里浮标被咬走、沉底、玩家转身，
都是**正常钓鱼过程**，但原来的 `no_bobber_frames` 照样累加，凑满 3 帧就停整个程序。

新增 `_set_calibrating(on)`：进标定打开 `suppress_abort` / `no_anchor_lock`
（复用飞行期那套开关），出来恢复原值并清零计数。

### ④ 咬钩新判据：`area_decayed()`

只看 y 轴位移会漏掉一类咬钩 —— 浮标被鱼拉着往下走，露出水面的部分越来越小，
中心点 y 变化可能不到阈值，但面积在明显衰减。

判据（取最近 1.2 秒内的面积样本）：

- 样本数 ≥ 3
- 末样本 / 首样本 ≤ 0.72（缩了 ≥28%）
- 整体单调不回升（允许 5% 抖动）

三条同时成立 → 判为咬钩，直接 `_loot()` 提竿。

**不误判的边界**（都有测试覆盖）：

| 序列 | 判定 | 原因 |
|---|---|---|
| 457 → 400 → 313 | 咬钩 ✔ | 0.69，单调缩小 |
| 457 → 消失 | 不判 ✔ | 样本不足 3；一步归零 |
| 400 → 450 → 410 | 不判 ✔ | 面积回升，是水面起伏 |
| 457 → 400 → 350 | 不判 ✔ | 0.77，缩小不足 |
| 超 1.2 秒窗口的旧样本 | 不判 ✔ | 已过滤 |

### ⑤ 亮团门槛自适应

`MIN_BRIGHT_PX_AT_ANCHOR = 90` 是在 1280×801 定的（浮标亮团 720 px，
最亮水面 56 px）。换到 720×529 后浮标只有 457 px，再降分辨率就会随机误拒 ——
表现为「同样的水面，有时认浮标有时不认」。

新口径：

```
门槛 = clamp(浮标指纹面积 × 0.35, 90, 指纹面积)
```

| 指纹面积 | 门槛 |
|---|---|
| 无指纹（首竿前） | 90（与 v48 一致） |
| 720 | 251 |
| 457 | 159 |
| 200 | 90（兜底） |

日志会同时打出实际门槛和指纹面积，方便核对。

## 四、这一版仍然没解决的

1. **`area_decayed()` 只在「当前帧完全找不到浮标」时判。** 如果浮标缩小到
   仍在检测范围内（比如 313 → 200 但一直有命中），y 位移又没到 strike 值，
   不会提竿。这类情况需要看下一轮实机日志再决定。
2. **0.72 这个衰减比是理论值。** 只用 v48 那一帧的 457→313 验证过，
   需要更多实机样本确认（尤其是小鱼/大鱼咬钩曲线是否不同）。
3. **1.2 秒窗口是估计值。** 真咬钩从开始下沉到消失的时长还不清楚。

## 五、怎么用

解压覆盖原目录，`run.py` 和 `fishingfun/` 同级即可。启动后日志第一行会显示
`v49`，确认是这一版。

建议第一次先这样跑，看「重抛」是否真的继续：

```
python run.py --frame-log 1
```

关注这几行：

- `→ 可恢复停机：本轮结束，0.35 秒后重抛（不退出）`
- `咬钩判定: 浮标面积渐进缩小至消失 → 判为咬钩`
- `锚点校验: ... （门槛 159 px，指纹面积 457）`
