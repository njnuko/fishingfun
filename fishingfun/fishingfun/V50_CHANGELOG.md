# FishingFun v50 更新说明

> 修复「首竿标定没等够 17 秒」。
> 问题不在计时器，在**判据把「浮标还在」判成了「浮标走了」**。

## 一、现象

真机（720×529 环境，2026-11-02 09:27）日志：

```
09:27:52,715  标定开始: 17 秒窗口
09:27:52,810  标定采样 01 t=2.8s y=114  area=485   ... 指纹否决26
09:27:54,997  标定采样 06 t=5.1s y=None area=0     ... 最佳=63x166 size=491 @(378,114) 指纹否决26
09:27:55,984  标定采样 07 t=6.0s y=None area=0     ... 最佳=38x166 size=482 @(378,114) 指纹否决29
09:27:56,985  标定采样 08 t=7.0s y=None area=0     ... 最佳=62x166 size=461 @(378,114) 指纹否决25
09:27:57,040  标定: 连续 3 帧未检测到浮标，提前结束采样（t=7.0s，判定浮标已离开画面）
09:27:57,041  标定采样: 5/8 帧命中，3 帧丢失（首次丢失 t=5.1s）
```

17 秒窗口只跑了 **4.3 秒**就断了。

## 二、根因（两层，第二层是真正的元凶）

### 第 1 层：`y is None` 被当成「浮标离场」

`sinkcalib.py` `run()` 里：

```python
# v49（错）
if y is None:
    miss_run += 1
    if miss_run >= 3 and i >= 5:
        break    # 判「浮标已离开画面」
```

`y is None` 有两个完全不同的成因，这里没区分：

| 成因 | 含义 | 该怎么办 |
|---|---|---|
| 画面里真的没有候选块 | 浮标被鱼拖走 / 飞出截屏区 | 可以提前结束 |
| **有候选，但被指纹判据否决** | 检测器自己判据太严 | **绝不能结束** |

日志证据：采样 06/07/08 三帧 `y=None`，但检测明细里写着
`最佳=63x166 size=491 @(378,114)`、`38x166 size=482`、`62x166 size=461`。
- 坐标三帧都在 `(378,114)` —— 一动没动，浮标明明在。
- 面积 461~491 vs 指纹 483 —— 差 1%~5%，几乎一模一样。
- 高度 166 vs 167 —— 差 0.6%。

只有**宽度**在 38~63 之间跳（指纹 47）。

### 第 2 层：指纹判据「任一维不符即整帧否决」

```python
# v49（错）
fa = fp["area"]; r = size / fa
if r < 0.3 or r > 3.0: n_fp_rej += 1; continue        # 面积
fr = fp["w"] / fp["h"]; cr = bw / bh
if cr / fr > 2.2 or fr / cr > 2.2: n_fp_rej += 1; continue   # 长宽比
```

浮标被鱼往下拉时，**露在水面上的部分变小 → 视觉上变窄成竖条**（高不变、宽减半）。
宽度恰恰是最不该单独否决的一维。一个维度抖动，整帧候选清零，
`find()` 返回 `None`，然后第 1 层逻辑就把它当成「浮标走了」。

## 三、v50 的修法

### 1. 指纹判据改「三维投票」

```python
votes = 0
if 0.4*fw <= bw <= 1.6*fw:  votes += 1     # 宽 ±60%
if 0.75*fh <= bh <= 1.25*fh: votes += 1    # 高 ±25%
if 0.65*fa <= size <= 1.35*fa: votes += 1  # 面积 ±35%
if votes < 2: 否决
```

真机四帧的票数（离线复算）：

| 帧 | 候选 | 宽 | 高 | 面积 | 票数 | 结果 |
|---|---|---|---|---|---|---|
| t=2.8s | 47×166 size=485 | ✓ | ✓ | ✓ | 3 | 通过 |
| t=5.1s | 63×166 size=491 | ✓(1.34×) | ✓ | ✓(1.02×) | 3 | 通过 |
| t=6.0s | 38×166 size=482 | ✓(0.81×) | ✓ | ✓(1.00×) | 3 | 通过 |
| t=7.0s | 62×166 size=461 | ✓(1.32×) | ✓ | ✓(0.95×) | 3 | 通过 |

反例（v43 踩过的顶部亮横带）仍在拦：

| 候选 | 宽 | 高 | 面积 | 票数 | 结果 |
|---|---|---|---|---|---|
| 80×34 size=1969 | ✗ | ✗ | ✗(4.1×) | 0 | 否决 |
| 95×34 size=2423 | ✗ | ✗ | ✗(5.0×) | 0 | 否决 |

### 2. 标定期区分「否决」和「离场」

```python
# v50
if y is None:
    rej  = getattr(self.finder, "_last_fp_rejected", None)
    note = getattr(self, "_last_detect", "") or ""
    if rej is not None or "@" in note:
        self._rejected_frames += 1      # 有候选，只是被判据挡了 → 不计 miss
    else:
        miss_run += 1                    # 真.画面里什么都没有 → 才允许结束
        if miss_run >= 3 and i >= 5: break
else:
    miss_run = 0
```

提前结束的日志也改了措辞：
`标定: 连续 3 帧画面内无任何候选，提前结束采样（t=X.Xs，判定浮标已离开画面）`

### 3. 锚点兜底

标定第一帧就撞上否决时，从检测明细里反查 `@(x,y)` 当本竿锚点，
不再整竿没有锚点：

```
标定锚点(本竿): 局部 (378,114)（取被否决候选 63x166 area=491）
```

### 4. 汇总日志多一行

```
标定采样: 5/8 帧命中，3 帧丢失（首次丢失 t=5.1s）
标定采样: 其中 3 帧「有候选但被指纹判据否决」（浮标没走，是判据太严；本竿锚点已用候选坐标兜底）
```

以后再出现类似情况，一眼能分清是**检测器问题**还是**浮标真走了**。
